
# Экономический режим FarmRPG Craft Calculator — полная спецификация (интегрированная)

> Все уточнения и доработки встроены в основной документ.

---

## 1. Общая концепция

Экономический режим — это надстройка над существующим крафт-калькулятором. Он позволяет оценить финансовую эффективность цепочки крафта: сколько потрачено ресурсов, сколько можно выручить, какую прибыль/убыток получить.

**Ключевая идея:** пользователь проходит привычный путь (локация → добыча → крафт → следующий крафт), а в любой момент может открыть экономический расчёт и увидеть цифры. Данные собираются автоматически, а цены вводятся вручную или подтягиваются из внешнего источника (Фауна).

**Режимы:**
- **Simple** — быстрый расчёт: скрипт сам строит оптимальную цепочку крафтов, максимизирующую прибыль, + список остатков.
- **Advanced** — полный контроль: ручное управление каждым остатком, динамический пересчёт, симуляция крафтов из остатков.

## 2. Компоненты интерфейса

### 2.1 Включение экономического режима
- В настройках (Settings) появляется переключатель (toggle) — `Enable Economy Mode`.
- При включении:
  - **Вместо** обычного интерфейса на главном экране появляются две кнопки: **"Locations"** и **"Craft"**. Они заменяют собой обычный стартовый экран калькулятора на всё время работы в экономическом режиме.
  - В правом нижнем углу появляется **золотая кнопка** (иконка с монетой из игры). Кнопка неактивна (серая), пока нет активной цепочки.
  - **Цепочка строится заново** — старая цепочка из обычного калькулятора не переносится. Это обеспечивает чистоту данных.
  - **Запрещена рекурсия** — после перехода к следующему крафту количество добытых ресурсов фиксируется и не может быть изменено задним числом.
- При выключении режима интерфейс возвращается к стандартному виду.

### 2.2 Золотая кнопка
- Состояние: **неактивна (серая)** — пока нет предметов в цепочке.
- Состояние: **активна (золотая)** — когда есть хотя бы один предмет в цепочке. На кнопке отображается количество предметов в цепочке (например, `💰 5`).
- **Действие:** нажатие открывает оверлей Simple-режима (3/4 экрана) поверх текущего интерфейса.

### 2.3 Оверлей Simple (по нажатию на золотую кнопку)
- **Содержимое:**
  - Список всех предметов в цепочке (от сырья до финального) с их количеством.
  - Под каждым предметом — поле для ввода цены (ручной ввод или кнопка "Заполнить из Fauna").
  - Кнопка **"Рассчитать"**.
  - Кнопка **"Add"** — для ручного добавления любого предмета в любом количестве (симуляция докупки на рынке). Добавленный предмет попадает в список остатков. Внизу списка появляется строчка-журнал: *"+5 Древесина (добавлено вручную)"*.
- **Результаты (после расчёта):**
  - Скрипт **сам строит цепочку крафтов**, которая даёт **наибольшую прибыль** с учётом введённых цен, доступных рецептов и курсов валют (комбинаторная оптимизация).
  - **Total Cost** — общая стоимость всех ресурсов (сумма цен на все предметы, которые были потрачены).
  - **Total Revenue** — выручка от продажи всех торгуемых остатков + выручка от продажи финального предмета (если цена введена).
  - **Total Profit** — разница между Revenue и Cost.
  - Список **leftovers** (остатков) — только те предметы, которые **торгуются** (передаваемые). Для каждого: название, количество, цена (если введена).
- **Предупреждение о неполных ценах:** если у какого-то передаваемого предмета из дерева крафта нет цены — появляется предупреждение: *"Список цен неполный. Для некоторых передаваемых предметов отсутствует цена. Расчёт может быть неточным."*
- **Кнопка внизу оверлея:** **"Открыть Advanced"** — создаёт/переключает на вкладку Advanced-режима (если ещё не создана).
- **Кнопка «Pin/Save»** — сохраняет текущий расчёт (включая цены и выбранные действия) в систему закрепления (Pinned). Расчёт попадает в специальную папку «Economy» (создаётся автоматически, если её нет). Пользователь может создавать свои папки для экономических расчётов и сортировать их.

### 2.4 Закрытие оверлея
- Крестик в углу → возврат к основному интерфейсу (крафт/локации).
- Данные (введённые цены) сохраняются в localStorage.

### 2.5 Вкладка Advanced (новая вкладка в хедере)
- **Название вкладки:** `Economy Advanced` (или просто `Advanced`).
- **Содержимое:**
  - **Хедер:** три показателя:
    - **C** — Cost (красная цифра)
    - **R** — Revenue (белая цифра)
    - **P** — Profit (зелёная цифра)
    - После каждой цифры — сокращение валюты (G/AP/OJ).
  - **Тело:** список всех остатков (leftovers) — каждый в отдельной строке.
  - Вкладка Advanced автоматически обновляется при изменении основной экономической цепочки (добавление новых предметов, изменение количества). При этом все введённые пользователем крафты и настройки цен сохраняются, если соответствующие предметы остались в цепочке.
  - В хедере вкладки также присутствует кнопка **«Pin/Save»** — сохраняет текущее состояние (все остатки, введённые крафты и цены) в папку «Economy».

### 2.6 Строки остатков в Advanced
- **Свёрнутая строка:**
  - Название предмета.
  - Количество (фиксированное, не редактируется).
  - **Хлебная крошка (breadcrumb):** после крафта строка превращается в `Дерево (10) → Стол (1)`. Промежуточные крафты (доски, wooden plank) **не показываются** в строке, чтобы не создавать визуальный шум. Хлебная крошка скроллится влево-вправо, если не влезает в строку.
  - **Клик на любой элемент** хлебной крошки откатывает состояние к этому элементу (все последующие крафты удаляются, а остатки пересчитываются).
- **Развёрнутая строка (по клику):**
  - Показывает список **всех** доступных крафтов, которые используют этот ресурс как ингредиент (даже если для них не хватает других ингредиентов — это позволит пользователю видеть полные возможности).
  - Для каждого крафта:
    - Название крафта + что получается (например, `→ Доски (1 древесина → 10 досок)`).
    - **Только цифровое поле** ввода (активное, редактируемое). Никаких крестиков. Нет ограничений — можно ввести любое число, даже если ресурсов не хватает (уйдёт в минус). Если пользователь вводит `0` — крафт удаляется (или считается неактивным).
  - После ввода числа — **мгновенный пересчёт всех ресурсов** (с debounce 300 мс). Хлебная крошка динамически обновляется при изменении количества.
  - Под строкой показываются **минус-строки** (не кликабельные): `-5 Древесина (использовано для крафта Досок)`.
  - Отрицательное количество (дефицит) не является ошибкой — это симуляция докупки ресурсов на рынке. Пользователь может вручную добавить недостающие ресурсы через кнопку **«Add»** или скорректировать цены.
- **Кнопка «Add»** — ручное добавление любого предмета в любом количестве. Добавленный предмет попадает в список остатков. Внизу списка появляется строчка-журнал: *"+5 Древесина (добавлено вручную)"*.

### 2.7 Хедер Advanced
- Три показателя:
  - **C** — Cost (красная цифра)
  - **R** — Revenue (белая цифра)
  - **P** — Profit (зелёная цифра)
- После каждой цифры — сокращение валюты (G/AP/OJ).
- Обновляются автоматически при любом изменении в списке.

## 3. Логика расчётов

### 3.1 Simple-режим
- **Вход:** цепочка предметов с количеством + цены на каждый предмет (введены вручную или из Fauna) + вручную добавленные ресурсы (через кнопку «Add»).
- **Алгоритм:**
  1. Скрипт **сам строит цепочку крафтов**, которая даёт **наибольшую прибыль** с учётом:
     - Введённых цен на все ресурсы.
     - Доступных рецептов.
     - Курсов валют.
     - Ручных добавлений (через «Add»).
  2. Рассчитать общую стоимость всех ресурсов, которые были потрачены на цепочку (сумма цен * количество для каждого предмета).
  3. Рассчитать выручку:
     - Выручка от продажи финального предмета (если цена известна).
     - Выручка от продажи всех торгуемых остатков (если цена известна).
  4. Вычислить Profit = Revenue - Cost.
  5. Сформировать список остатков только для **торгуемых** предметов (если предмет не торгуется — не показывать, или показать без цены, с пометкой "не торгуется").
- **Предупреждение:** если у какого-то передаваемого предмета из дерева крафта нет цены — появляется предупреждение о неполноте цен.
- **Вывод:** оптимальный путь (готовый), цифры (Cost, Revenue, Profit) + список остатков.

### 3.2 Advanced-режим
- **Вход:** цепочка предметов с количеством + цены на каждый предмет (введены вручную или из Fauna) + ручные крафты (количество, введённое пользователем для каждого остатка) + вручную добавленные ресурсы (через «Add»).
- **Алгоритм:**
  1. Начальное состояние: список остатков (из цепочки) с фиксированными количествами.
  2. Пользователь вводит количество крафтов для одного из остатков (только цифровое поле).
  3. Пересчёт:
     - Списываются ресурсы, которые пошли на крафт (из строки, где был ввод). Количество может стать отрицательным (дефицит).
     - Добавляются новые ресурсы (результаты крафта) — они попадают в список остатков (если ещё не были там) или увеличивают существующие строки.
  4. Для каждого ресурса в списке:
     - Если количество >= 0 — строка зелёная/нейтральная.
     - Если количество < 0 — строка красная (дефицит).
  5. Под каждой строкой (если были крафты) — минус-строки (не кликабельные), показывающие, сколько ресурсов и на что было потрачено.
  6. Хлебная крошка динамически обновляется. Клик на любой элемент откатывает состояние.
- **Вывод:** динамически обновляемый список остатков с возможностью бесконечного пересчёта.

## 4. Настройки

### 4.1 Валюта расчёта
- В настройках (Settings) — выбор валюты для отображения всех цифр (Cost, Revenue, Profit).
- Три валюты:
  - **Gold** (золото)
  - **AP** (Action Points)
  - **OJ** (Orange Juice)
- Выбранная валюта влияет только на **отображение** — все расчёты внутри ведутся в той валюте, в которой введены цены. Если цена введена в другой валюте — используется курс конвертации.

### 4.2 Курсы валют
- **Три валюты:** Gold, AP, OJ.
- В настройках есть три поля для ручного ввода курсов (или если данных нет — они пустые):
  - 1000 AP = X Gold
  - 1000 OJ = X Gold
  - 1000 OJ = X AP
- Курсы используются для конвертации цен, когда предмет имеет цену в одной валюте, а отображение ведётся в другой.
- Если курс не задан — предмет с ценой в другой валюте просто не отображается (или показывается как "цена неизвестна").

### 4.3 Кнопка конфигурации
- В настройках (рядом с выбором валюты) — кнопка **"Configure Prices"** (или иконка шестерёнки).
- Открывает таблицу/список, где:
  - Перечислены все предметы, которые встречались в цепочках (или все предметы из игры, если есть данные).
  - Для каждого предмета: поле для ручного ввода цены.
  - **Тоггл "refreshable"** (галочка/переключатель) для каждого предмета:
    - Если тоггл включён — цена **перезаписывается** при обновлении из Fauna.
    - Если тоггл выключен — цена **остаётся** без изменений (ручной ввод имеет приоритет).
    - По умолчанию все цены — refreshable (чтобы обновлялись).
  - Индикатор: цена из Fauna (если есть) или ручная.
  - Приоритет: если цена введена вручную и тоггл refreshable выключен — она используется, даже если есть данные из Fauna.
- **Сохранение:** все введённые цены сохраняются в localStorage.

### 4.4 Данные Fauna
- Данные Fauna **не подтягиваются напрямую в браузер**.
- Настроен **GitHub Actions**: раз в N часов (или по триггеру) скрипт забирает JSON от Фауны, коммитит и пушит в репозиторий.
- Пользователь получает данные **из репозитория** (через обычный JSON-файл, как и все остальные данные).
- Если у Фауны всё упадёт — последние полученные данные останутся в репозитории и будут доступны.
- Кнопка **"Refresh from Fauna"** — ручное обновление цен из репозитория (фактически — перечитывание JSON-файла).
- Если у Fauna нет цены для предмета — поле остаётся пустым, пользователь вводит вручную.
- Ручной ввод имеет приоритет над данными Fauna, если тоггл refreshable выключен.

## 5. Технические требования

### 5.1 Модули
- Новый модуль: `src/utils/economyCalculator.js`:
  - `calculateCost(chain, prices)` — общая стоимость ресурсов.
  - `calculateLeftovers(chain, prices, isTradable)` — список остатков (только торгуемые).
  - `applyCraft(leftovers, itemId, quantity, craftRecipe)` — пересчёт после крафта (для Advanced).
  - `runSimple(chain, prices)` — полный расчёт для Simple-режима (включая комбинаторную оптимизацию).
  - `runAdvanced(chain, prices, actions)` — полный расчёт для Advanced-режима.
  - `findOptimalPath(chain, prices, recipes, exchangeRates)` — поиск оптимальной цепочки крафтов для максимизации прибыли.
- Основной модуль крафта `calculator.js` — остаётся без изменений.

### 5.2 Состояние (State)
- Использовать существующий стейт (Redux/Context) для:
  - `economyChain` — все предметы в текущей цепочке.
  - `prices` — введённые цены (по ключу `itemId: { gold, ap, oj }`).
  - `currency` — выбранная валюта отображения.
  - `exchangeRates` — курсы конвертации.
  - `advancedState` — для Advanced-режима: список крафтов, введённых пользователем.
  - `manualAdditions` — журнал ручных добавлений (через кнопку «Add»).
  - `priceRefreshable` — состояние тоггла refreshable для каждого предмета.
- Сохранять все данные в localStorage (автоматически при любом изменении).
- Экономическая цепочка (`economyChain`) — это отдельное состояние, не связанное с обычным калькулятором. Она хранит все предметы, добавленные пользователем в экономическом режиме. Для управления используются хуки `useEconomy` и `useCraft` (последний — только для получения рецептов, но не для хранения цепочки). Все изменения сохраняются в localStorage с префиксом `economy_`.

### 5.3 Производительность
- Пересчёт в Advanced-режиме должен быть **асинхронным** (фоновым) с debounce (300 мс после последнего ввода).
- Обновление UI — только изменённые строки (React.memo).
- Для больших цепочек (50+ предметов) — пагинация или виртуализация списка.
- **Лимит цепочки:** максимальная длина — **100 предметов**. При попытке добавить 101-й предмет — предупреждение: *«Достигнут лимит цепочки (100 предметов)»*, добавление блокируется.

### 5.4 Интеграция с Fauna
- **GitHub Actions:** раз в N часов (или по триггеру) скрипт забирает JSON от Фауны, коммитит и пушит в репозиторий.
- Хранение: JSON-файл в репозитории (например, `data/fauna-prices.json`).
- Фронтенд: чтение JSON-файла из репозитория (как и все остальные данные).
- Кэширование: данные хранятся в localStorage с временем жизни (TTL) — например, 1 час.

## 6. Данные

### 6.1 Источники данных
- **Цепочка крафта:** из существующего калькулятора (база данных рецептов).
- **Остатки (leftovers):** из данных по локациям (exploration data) — какие ресурсы падают вместе с целевыми.
- **Цены:** ручной ввод + Fauna (через JSON-файл в репозитории).

### 6.2 Торгуемые предметы
- Список предметов, которые можно передавать (tradeable) — берётся из игры.
- Если предмет не торгуемый — он игнорируется в расчёте выручки (или показывается без цены).

### 6.3 Побочные продукты (leftovers)
- **Откуда берутся:** из данных по локациям (дропы). При фарме целевого ресурса автоматически выпадают побочные ресурсы.
- **В цепочке:** leftovers появляются на этапе добычи сырья, а не на этапе крафта. Крафт не создаёт побочных продуктов.

## 7. Итоговый UX-сценарий

1. **Включение режима:** настройки → Economy Mode ON → на главном экране появляются кнопки "Locations" и "Craft" (вместо обычного стартового экрана) + золотая кнопка (неактивна). Цепочка строится заново.
2. **Сбор цепочки:** пользователь добывает ресурсы (Locations) и крафтит (Craft). Золотая кнопка становится активной, показывает количество предметов в цепочке.
3. **Simple-расчёт:** нажатие на золотую кнопку → оверлей с полями цен → кнопка "Add" для ручного добавления ресурсов → кнопка "Рассчитать" → скрипт находит оптимальный путь → вывод Cost, Revenue, Profit + список остатков. Если цены неполные — предупреждение.
4. **Сохранение Simple:** кнопка "Pin/Save" → расчёт сохраняется в папку «Economy».
5. **Переход в Advanced:** в оверлее Simple нажать "Открыть Advanced" → вкладка Advanced (или создаётся новая) → все данные переносятся.
6. **Advanced-симуляция:** пользователь разворачивает строки остатков, видит хлебную крошку, вводит количество крафтов (только цифры) → мгновенный пересчёт → видит дефицит (красные минусы) → хедер обновляет C, R, P. Клик на элемент хлебной крошки откатывает состояние.
7. **Ручное добавление:** кнопка "Add" → добавить любой предмет → журнал внизу списка.
8. **Корректировка цен:** при необходимости пользователь идёт в настройки → меняет курс валюты (1000 AP/1000 OJ → Gold) или вручную правит цены с учётом тоггла refreshable.
9. **Сохранение Advanced:** кнопка "Pin/Save" → текущее состояние сохраняется в папку «Economy».
10. **Автосохранение:** все изменения сохраняются автоматически (localStorage с префиксом `economy_`).

## 8. Взаимодействие с обычным калькулятором

- Обычный калькулятор не знает о существовании цен и экономического режима.
- Экономический режим использует данные из обычного калькулятора (рецепты, предметы), но не изменяет их.
- Цепочки, построенные в экономическом режиме, не влияют на стандартный крафт.
- При включении экономического режима цепочка строится заново (не переносится из обычного калькулятора).
